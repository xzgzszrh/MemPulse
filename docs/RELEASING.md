# 开源发布准备

## 目录约定

工作区保留相邻的 `MemPulse/` 与 `OpenCode/`，避免破坏服务发现和打包路径。说明文档集中到根或组件 `docs/`；README、LICENSE、AGENTS、构建配置、锁文件、运行资源、测试夹具和工具约定文件保留在必要位置。

技术报告和比赛材料移至工作区旁的 `Kylin-Mem-private/`。历史构建、过程稿与本地状态移至 `Kylin-Mem-cleanup-backup-20260917/`，迁移清单为该目录的 `moves.json`。这些目录不属于开源源码。

完整模型目录随源码交付，并在导出前逐文件校验；模型大文件由 Git LFS 管理。本地依赖与虚拟环境由导出工具排除，可由构建入口重新安装。评测脚本仍可向 `reports/` 写入新结果，但该目录不纳入发布。

## 生成独立源码

在工作区根目录运行：

```bash
python3 scripts/export_source.py --output ../Kylin-Mem-public
```

工具复制当前工作文件，包含尚未提交的源码改动和独立 WebUI，包含完整模型包；排除两套 Git 历史、被忽略文件、数据库、构建物与过程材料；目标必须不存在。导出后在新目录初始化 Git，执行 `git lfs install`，再按实际 GitHub 仓库地址设置 remote。`.gitattributes` 已指定 ONNX 和 safetensors 使用 LFS；提交前确认大文件已进入 LFS。不要直接推送现有组件历史：历史中曾包含评测记录及其他已移除材料。

不要用麒麟模型交付脚本替代公开源码导出；前者面向带模型的本机交付，仍要求两个组件已有干净提交。
